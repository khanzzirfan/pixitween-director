# 31 Oct 2026: the 3D hero clip

A product clip where the real product is a 3D model that tumbles in, turns under a moving light and rides a dolly zoom, with the name and price on top. It is the `hero-3d` look. The catalogue picks it for tall round packs (cans and bottles) that are not on sale; everything is built from the shop's own photo, offline, at no model cost beyond the cut-out.

Status (31 Oct 2026): built, tested, run live on the six-product sample feed, and viewed in the browser. It needs `reacthub-pixitweenjs` 0.3.5 or newer.

## What it looks like (5 s, 9:16)

| Time | What happens |
|------|--------------|
| 0.0 - 0.8 s | The can tumbles in from above, tilted in the frame and spinning fast, and lands upright |
| 0.8 - 3.0 s | A slow three-quarter turn while the key light runs across the label (a real light, not a painted highlight) |
| 1.0 s | The price disc pops on the beat, then pulses every second beat. A sale shows the old price with a red strike line that pulses with it |
| 3.0 - 4.0 s | Dolly zoom: the lens widens from 20 to 80 degrees while the can holds its size on screen. The halo and bokeh behind it grow, which gives the vertigo read |
| 4.0 - 5.0 s | Hold, so the price can be read |

The world is a dark brand-colour field, a warm halo behind the can, a floor glow, eight soft bokeh discs and a 2D contact shadow. The name types in word by word; the brand sits above it in capitals. Everything is deterministic: the same input gives the same film.

## How it is built

```
CSV feed ──► SAM cut-out ──► prepareRound ──► pickLook ──► buildCatalogClip ──► clip JSON
                              (label unwrap,   (round: true    (hero-3d or the
                               free)            gives hero-3d)   2D retail clip)
```

| Piece | File | Job |
|-------|------|-----|
| `buildHero3DClip` | `server/authoring/hero3d-clip.ts` | The clip itself: scene, tumble, turn, light, dolly, copy. Beat times are exported as `HERO3D_BEATS` |
| `prepareProduct3D` | `server/product3d/prepare.ts` | Unwraps the cut-out into a 2048 by 1024 label and finds the side colour (see [3d.md](../3d.md)) |
| `prepareRound` | `server/authoring/catalog-clip.ts` | Runs `prepareProduct3D` for tall can or bottle cut-outs only; returns nothing for anything else, so those stay 2D |
| `pickLook` | `server/authoring/looks.ts` | Takes a new `round` input. Tall and round gives `hero-3d`; a sale still gets `price-promo`; short or flat packs keep their 2D looks |
| `buildCatalogClip` | `server/authoring/catalog-clip.ts` | One call per product: the 3D hero for `hero-3d`, the 2D retail clip otherwise |
| `s19-catalog` | `scripts/live/s19-catalog.ts` | The live catalogue run; prepares labels after the cut-outs and skips plate generation for 3D products |

### Try it

Offline and free, on a cut-out already in `./data/assets`:

```bash
npx tsx scripts/hero3d-demo.ts [cutoutAssetId] [aspect] [out.json] [--sale]
```

It writes `web/public/cartoon/hero3d-clip.json`. Open it at `/stage-check.html?film=live&file=/cartoon/hero3d-clip.json` (the API server must be running, because the label is served from `/api/assets/...`).

The catalogue run costs about $0.005 for the sample feed (one SAM cut-out per distinct photo). It prints an estimate and does nothing without `--yes`; give it its own data dir:

```bash
DATA_DIR=./data-s19-hero3d npm run live -- s19-catalog --yes
```

Copy the new assets from that data dir into `./data/assets` to view them.

Result on the sample feed: Cold Brew and Vanilla Cold Brew got `hero-3d`; Mocha and Stone Mug (on sale) got `price-promo`; Sage and Night Mug got `lifestyle-room`; two variant films were built.

## Why the dolly zoom is real

A dolly zoom keeps the subject the same size while the perspective changes. The engine frames the camera from the lens angle at every frame, so animating `camera.fov` does exactly that: nothing about the can moves or scales. The first version faked it by scaling and moving the can and the can shrank; the engine fix below replaced it.

## Engine changes (reacthub-pixitweenjs 0.3.5)

| Change | Where | Effect |
|--------|-------|--------|
| `camera.fov` is animatable | `src/types/aep/layer.ts`, `model3d/sampleModel3D.ts` | A 3D layer's lens angle can carry keyframes. Documented in the model3d integration page of the engine docs |
| Soft shadow edge | `model3d/framing.ts`, `model3d/shadowFade.ts`, `Pixi3DModelLayer.tsx` | The shadow plane fades to nothing at its edge instead of ending in a hard dark slab |

Both have unit tests in the engine (1258 pass, 2 expected failures). The clip keeps the engine's 3D shadow off and draws a 2D contact shadow, which reads better at this camera angle; the soft shadow is there when wanted.

The director's mirror schema (`server/product3d/types.ts`) accepts animated fov too, and `web/src/authoring-agreement.test.tsx` checks the built clip against the real engine schema and the light validator.

## Other fixes made on the way

- **Play button stuck on Pause** after a clip ended: the player kept its own play state while the engine rewinds and pauses itself at the end. The button now follows the engine's state every frame (`web/src/player/Player.tsx`, with a test).
- **Compact check page:** `stage-check.html` caps the stage at 60 % of the window height so the controls stay in view.
- **Player quirks found earlier** (still in [KNOWN-GAPS.md](../todos/KNOWN-GAPS.md)): layer rotation is read as radians, so builders convert with `deg()`; track mattes draw empty.

## Limits

- The label covers only the photo's front arc: about 70 degrees either side. Past that it is the side colour. The fast spin on entry hides this; a slow full turn would show it.
- Only cans and bottles are tried in 3D. Mugs, boxes and odd shapes stay 2D for now (`ROUND_NOUNS` in `catalog-clip.ts`).
- No liquid splash, pour or droplets: the engine has no particle or fluid system.
- Needs the API server for the label image; without it the can does not draw and the rest of the clip still plays.

## Running the viewer

Use `npm run dev` (API server and web server together). If the page shows `engine schema: errors ... camera.fov`, the dev server is serving an old engine from its cache; restart it with `--force`.
