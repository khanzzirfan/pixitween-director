# R8: Director films on the Three engine (close the converter gaps, one rotation unit, parity guard)

Makes the Three.js engine the only way our director films are checked and played. Closes the four things the AEP converter silently drops on our retail clip and variant film (image effects incl. drop shadow and blur, soft-light blend, polystar shapes, rotation units), removes the radians workaround from the authoring code, and adds a guard so a film can never again lose a feature without a failing test. Leaves out new cinematic features (fake dolly zoom, ingredient cloud, lit 3D can): those are the next PRD.

### US-001: One rotation unit: degrees, with a flag for old films

As a film author, I want layer rotation to mean degrees everywhere so that a 22 degree tilt looks like 22 degrees on the Three engine and nobody needs a radians workaround.

**Steps**

1. Read engine/docs/02-timeline.md and 03-stage-2d.md on rotation, then web/src/motion/aep/baseLayer.ts and keyframes.ts to see how AEP `transform.rotation` is passed to the engine as-is today, and shared/aep/transform.ts for what the AEP schema says the unit is.
2. Read server/authoring/retail-clip.ts, variant-film.ts and hero3d-clip.ts: each has a `deg()` helper that converts degrees to radians because the old Pixi player read radians. Count every stored film under data/films/*/versions/*.json with a non-zero rotation (write a throwaway node script in debug/app/) and record the count in `notes`.
3. Add an optional `rotationUnit: 'deg' | 'rad'` to the composition's `meta` handling: in server/authoring/composition.ts newFilmComposition() writes `meta.rotationUnit = 'deg'` on every new composition. A composition without the field is a legacy film and its rotations are radians.
4. In web/src/motion/aep/baseLayer.ts read `rotationUnit` (thread it from aepToMotion in index.ts through convertLayers and each converter; precomps inherit from their parent unless they set their own). When the unit is 'rad' (or absent) multiply every rotation value, static and every keyframe, by 180/PI before it reaches the engine; when 'deg' pass through.
5. Add tests in web/src/motion/aep/baseLayer.test.ts: a legacy layer with rotation 0.383972 gives 22.0 degrees (within 0.01); a 'deg' layer with 22 gives 22; a keyframed rotation converts every key; a precomp inherits the flag.
6. Check shared/aep and the AEP JSON schema for a `meta` object that allows the new field; extend the zod schema only if it strips unknown keys.

**Acceptance criteria**

- [ ] aepToMotion on a composition with meta.rotationUnit 'deg' and a keyframed rotation [-22, 4, 0] produces tween values -22, 4, 0 on the MotionDoc layer
- [ ] aepToMotion on a composition without meta.rotationUnit and rotation [-0.383972, 0.069813, 0] produces values within 0.01 of -22, 4, 0
- [ ] newFilmComposition() output has meta.rotationUnit === 'deg'
- [ ] Every stored film under data/films still converts with the same number of warnings as before this story

### US-003: Layer effects on every layer: drop shadow, blur, glow, tint, levels

As a film author, I want effects on image, shape and text layers to reach the Three engine so that cans keep their contact shadows and the plate keeps its blur.

**Steps**

1. Read web/src/motion/aep/layers2d.ts convertEffects (it only runs for shapes and handles gaussian-blur), text.ts (it reads one drop-shadow), shared/aep/effect.ts, and engine/src/effects/table.ts plus engine/src/effects/custom/dropShadow.ts for the engine's param names and units.
2. List how our films write each effect (grep `drop-shadow` and `gaussian-blur` in server/authoring/retail-clip.ts and variant-film.ts): AEP drop-shadow params are distance, direction (180 means straight down), softness, opacity, color; gaussian-blur is blurriness.
3. Create web/src/motion/aep/effects.ts exporting convertEffects(layerId, effects, compSize, warnings): the single place that maps AEP effects to engine effects. Map drop-shadow -> dropShadow (color, alpha = opacity, distance scaled by the same comp-size/960 factor used for blur, angle converted from AEP direction to the engine's angle convention: read dropShadow.ts and test it so 180 gives a shadow below the layer, blur from softness), gaussian-blur -> gaussianBlur (existing scale rule), glow -> glow, brightness-contrast -> brightnessContrast, hue-saturation -> hueSaturation.
4. Anything else (levels, curves, tint, fill, tritone, fast-box-blur, color-balance, directional-blur) stays unsupported and produces one warning `layer <id>: unsupported effect '<name>'`.
5. Make shape, image and text converters call the shared convertEffects (image currently sets effects to an empty list; text keeps its dedicated text-shadow only if the shared path cannot do it, and say which in notes).
6. Create web/src/motion/aep/effects.test.ts: one case per mapped effect with the engine params asserted, the direction 180 case, an unsupported effect warning, and a layer with two effects keeping their order.
7. Add the converted effects to layers2d.test.ts for an image layer with drop-shadow and gaussian-blur.

**Acceptance criteria**

- [ ] An AEP image layer with drop-shadow {distance 40, direction 180, softness 30, opacity 0.5, color #000000} converts to an image layer whose effects list holds one dropShadow with alpha 0.5 and the distance scaled by max(compW, compH)/960
