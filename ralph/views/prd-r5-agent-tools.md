### US-002: QA report model and 2D checks (offstage, clipped, text size and pace, overlap, pop)

As an agent, I want grouped QA findings with the worst frame and a concrete hint so that I can fix the biggest problem first and recompile.

**Steps**

1. Read engine/docs/08-agent-tools.md section 'QA' (group shape, kinds, limits, hints).
2. Create engine/src/agent/qa.ts exporting QaKind, QaGroup, QaReport, QA_LIMITS and qaDoc(doc, bake?, limits?) with the group-building logic (consecutive failing frames per subject and kind become one group with count, first, last, worst, worstFrame) and the 2D checks OFFSTAGE, CLIPPED, TINY_TEXT, FAST_TEXT, TEXT_OVERLAP, POP and NEVER_SEEN; each hint names numbers (pixels, seconds, sizes) computed from the bake.
3. Add the optional doc field qa: { limits } to engine/src/schema/doc.ts (shared edit) and merge it over QA_LIMITS.
4. Create engine/src/agent/qa.test.ts with small docs built in the test, one per kind, plus a clean doc.

**Acceptance criteria**

- [ ] A doc where every layer stays on stage, text is 64 px at 1080 high, readable for 3 s and not overlapping gives ok true and no groups
- [ ] A text layer at x 2400 on a 1920 wide stage gives one OFFSTAGE group whose hint contains an x value inside the stage
- [ ] A 20 px text at 1080 high gives TINY_TEXT with limit about 38 and a hint naming a scale or fontSize that meets it
- [ ] Two readable text layers overlapping by 30 % give one TEXT_OVERLAP group naming both ids; a 'set' tween that moves x by 900 px mid-life gives POP with that frame as worstFrame
- [ ] A layer with alpha 0 throughout gives NEVER_SEEN; warnings never change ok

### US-005: applyEdit and undoEdit: atomic ops, revisions, deterministic receipts, exact inverse

As an agent, I want edits that return a receipt, refuse stale revisions and undo exactly so that I can change a doc safely in many small steps.

**Steps**

1. Read engine/docs/08-agent-tools.md section 'Receipts and undo'.
2. Add the optional integer field revision (default 0) to the doc schema (shared edit).
3. Create engine/src/agent/edit.ts exporting EditOp, Receipt, applyEdit and undoEdit as specified: refuse STALE_DOC on revision mismatch, NOT_FOUND for unknown layer, tween or effect, INVALID (with explainDoc errors) when the result does not parse, all ops atomic; revision + 1 on success; receipt id = a short stable hash of revisionBefore and the JSON of the ops; inverse ops computed before applying; affected lists layer ids; qa summary from qaDoc on the result.
4. Create engine/src/agent/edit.test.ts.

**Acceptance criteria**

- [ ] applyEdit with expectRevision 0 on a revision 0 doc returns revisionAfter 1; the same call with expectRevision 5 returns STALE_DOC and leaves the input unchanged
- [ ] For each op kind, applying the receipt's inverse to the result gives a doc deep-equal to the original (except revision, which increases)
- [ ] Two identical applyEdit calls produce the same receipt id
- [ ] A batch whose second op is invalid changes nothing and returns INVALID with at least one explain error
- [ ] `npm run typecheck` passes
- [ ] `npm test` passes (offline, no network)
